# ghx-deps

> **v0.1.0, alpha.** Part of [LIMEN Labs Public](https://github.com/ferall0gic/LIMENLABSPUBLIC). The test suite uses synthetic files. On Windows, the dependency comparison was also checked against the original and fixed [Simple Tent definitions](https://github.com/jhorikawa/GrasshopperHowtos/tree/162e1ce72a5587dc797ae9cc8a721eae6401fab2/0096%20Simple%20Tent), [Speckle sample](https://github.com/specklesystems/GrasshopperAsyncComponent/blob/6a379d9d4f3e13f99347d9af994f63a4295cc4cf/SampleGhFile.ghx), and [McNeel component-data definition](https://github.com/mcneel/rhino.inside-revit/blob/d61a17e79608be620d7d1f5b41059ffe058eafd7/docs/update_components_data.ghx).

`ghx-deps` reads Grasshopper `.ghx` definitions without Rhino and lists what each one needs: the plug-in libraries recorded in the file (name, version, author, Id), the components it uses (by name and type GUID), any script components, clusters, and absolute file paths baked into the definition. Point it at one file or a whole project folder. It prints Markdown or JSON. With an **allowlist** it becomes a CI gate that fails when a definition needs a plug-in your office hasn't approved.

It uses the Python standard library only. Grasshopper, Rhino, and GH_IO.dll are not needed or loaded, and files are never modified.

## Install (from a checkout)

```text
python -m pip install ./ghx-deps         # Python 3.10+; no dependencies
python -m pip install -e "./ghx-deps[test]" && python -m pytest ghx-deps/tests
```

## Use

```text
ghx-deps facade.ghx
ghx-deps definitions/ --format json --output deps.json
ghx-deps definitions/ --allowlist office-plugins.txt
ghx-deps facade.ghx --allow MeshKit --allow bbbbbbbb-0000-4000-8000-000000000002
```

An allowlist is a text file with one library name or library Id per line. `#` starts a comment, and matching ignores case. An empty allowlist means "core Grasshopper only".

| Exit code | Meaning |
|---|---|
| 0 | All files read; nothing outside the allowlist (or no allowlist given) |
| 1 | All files read; a definition needs a library that is not on the allowlist |
| 2 | A file could not be read (including binary `.gh`), or bad arguments |

## What it reads, and what it can't see

- **Libraries** come from the definition's own `GHALibraries` list, which Grasshopper writes when it saves. If an older Grasshopper didn't record a library, `ghx-deps` can't report it.
- **Components** are counted by their stored name and type GUID at the top level of the canvas. Plug-ins used only inside a **cluster** may be missing from the component counts. Clusters are counted so you can check them by hand.
- **Script components** (C#, VB, Python) are flagged by name. Libraries their code imports are not detected.
- **File paths:** text values that look like absolute paths ending in a known file extension are listed. This is a heuristic, so it can miss paths or list ones that aren't really used.
- **Binary `.gh` files are not supported** in v0.1. They are reported as not read (exit 2). Save as `.ghx` in Grasshopper first. Reading `.gh` would mean reimplementing GH_IO's binary format, which is not done here.
- XML is parsed with Python's `xml.etree.ElementTree`, which does not fetch external entities. Still, only run it on files you would open in Grasshopper anyway.

Tested on synthetic `.ghx` fixtures (generated by `scripts/make_fixtures.py`) on Linux, Python 3.10 and 3.13. Also spot-checked by hand on two openly published `.ghx` files, which are not included in this repository.

## Compare two revisions

Install the package as above, then run:

```console
ghx-deps-diff previous.ghx current.ghx
ghx-deps-diff previous.ghx current.ghx --json --check
```

Each changed record shows its count before and after. A plug-in version change produces two rows, one for the old version and one for the new. Components are grouped by recorded name and type GUID. Absolute file references use the same detection rules as `ghx-deps`, with each distinct path counted once. Reordering components has no effect. Edits to wiring, scripts, or parameter values are outside the comparison unless they also change a recorded dependency.

JSON output is an array of changes, empty when the inventories match. A successful comparison exits 0. With `--check`, changes exit 1. Unreadable or invalid input exits 2 and writes a diagnostic to stderr.
## Inspect canvas groups

Use `ghx-groups design.ghx` for a text outline of the groups on the top-level canvas and the components they contain. Add `--json` to get an array of groups, each with its instance ID, nickname and direct members. Nested groups appear as direct references. Each member has its instance ID and the resolved object's name and nickname. A missing reference has a null object. Empty groups are included. A valid definition without groups yields an empty array. The command returns 0 on success or 2 for bad input.

### Canvas notes and wire reports

Install with `python -m pip install ./ghx-deps` from the repository root.

- `ghx-notes design.ghx` exports the saved text, nickname and instance ID of each top-level Panel or Scribble. Line breaks and empty notes are preserved. For wired panels the text is the saved UserText field, not evaluated upstream data.
- `ghx-wires design.ghx` exports one row per serialized source reference with source and target port IDs, names and owning objects. It reads standalone parameters and the legacy and ParameterData component port layouts. Unknown source IDs remain visible with a null source. It does not traverse cluster interiors or run the solver.

Both commands emit a JSON array to stdout in archive order. Redirect output to a file to keep a report. An empty report is a successful read (exit 0). Unreadable or invalid definitions exit 2 and write a diagnostic to stderr.
